Alta Today Redesign
Alta design exercise · Part 6 · Prototype v6 — three-level type system

Today, v6: three sizes, five styles

v6 reduces the whole app to three type sizes (28 / 16 / 13 px), five styles and two text colours, and makes the tab bar icon-only like the original. v5 cut Home copy roughly in half and lifted the look card as the one elevated object on screen. Before that, v4 responded to the visual review of v3: fewer pill shapes and shadows, more air, the outfit shown on a model with the clothing set beside it, and motion on the key interactions. Flows are the same as the tested v2. Version 2 of the interactive prototype, after a pain-point-based usability test (11 findings) and an interaction walkthrough (11 fixes). Green tags in the panel (F1–F11, W1–W11) mark what changed and why. Home leads with one outfit from your own closet and a one-tap "Wear this today." Add Items asks only about what the AI is unsure of, then shows what your effort unlocked. Tap through it on the phone; the panel explains each decision.

Images are not final. The model and clothing pictures in this prototype are placeholder illustrations. The final product would use real photography or Alta's own avatar render.

Hierarchy

Four levels, top to bottom

1 · the day (title, weather, tabs) → 2 · the look (model + set) → 3 · one action → 4 · what's next (Wear again, Partner). Each level gets one treatment.

Shapes

One pill: the main button

Day-type chips became text tabs with a sliding underline. Swap, Save and Ask are text actions. Cards became hairlines. The tab bar is flat again, like the original.

On the model

See it on you; check what it is

The outfit is drawn on a model so it reads as a look, and the clothing set sits right beside it, labelled "From your closet." Production would use Alta's existing avatar render.

Why it should work

How the design moves weekly retained outfit planners

The metric counts users who come back in a later week and select or plan at least one outfit. The redesign shortens the path to that event, adds a second path to it (planning in the evening), and feeds recommendation quality through easier input.

Primary
  • Weekly retained outfit planners (north star)
  • Open → wear/plan conversion per session
  • Time to decision: target under 15 s from app open
Input health
  • Items added per upload session ↑
  • Upload completion rate (started → finished) ↑
  • Post-add edit rate on auto-added items — catches silent AI errors
Guardrails
  • Partner card: click-through vs. today's feed; dismiss rate
  • Undo rate on "Wear this today" and batch adds
  • Swipe-past rate on the first hero look (is the top pick trusted?)
Design system

Five components, reused everywhere

The review asked for no one-off patterns. The whole prototype is built from five components, so the same pieces can later rebuild the Calendar view.

Context chips

Single-select pill row. Day type on Home, answers in Add Items, categories in item edit.

Used in: Home, Review, Edit sheet
Hero look

Large flat-lay or avatar render, ownership badge, reason line, swipe between up to 3 pre-rendered looks.

Used in: Home
Outfit tile

One consistent representation for any outfit: fixed ratio, caption, meta. Fixes the mixed avatar/collage problem.

Used in: Wear again, Unlocked looks, Plan card, Calendar (future)
Partner card

The only commercial surface. Distinct border and "Partner" label, justified by outfits it completes, always dismissible.

Used in: Home
Question card

One AI uncertainty → one question → chip answers. Collapses into a confirmed row when answered.

Used in: Review
Content rules

Say what the user does ("Wear this today"), not what the system does ("Log"). Questions over commands. Label anything for sale.
